Image production sheet

Every image the storefront still wants, with the prompt that makes it, the exact filename it must be saved under, and the folder it goes in. Drop the file in the folder and the site picks it up — no code is edited.

2026-09-03 · three assets, seven prompts · $0.00 spent generating (no OPENAI_API_KEY in this environment)

Read this before generating anything. The fifteen reference images in images/ are an AI mockup of a fictional shop called “Digital Bookstore”. They carry other publishers' covers, synthetic portraits of real living authors, and invented numbers — 50K+ books, 2M+ readers, 4.8 ★ on titles with no reviews. They are a reference for layout only. Nothing below asks for a book, a face, a rating or a count, because this press has nine books, one living author and zero reviews, and the storefront says so.

The one image on this list that must not be generated is a photograph of you. A synthetic portrait of a real person, presented as that person, is exactly what was removed from this site in Phase 4. If you want a face on /authors and /about, take or supply a real photograph: public/images/authors/emre-dogan.webp, 3:4, at least 900 px tall. Until then the designed ED monogram stands, and it is honest.

How to use this sheet

  1. Copy a prompt out of its box.
  2. Generate the image at the stated pixel size. Any generator; the prompts are written to be model-agnostic.
  3. Save it under the exact filename given. The site resolves images by convention — a different name resolves to nothing.
  4. Put it in the exact folder given.
  5. Run node scripts/assets/asset-manifest.mjs --write and commit. npm test fails if you forget this step, which is the point.

Save as WebP if your tool offers it. If it only gives PNG or JPEG, convert: cwebp -q 82 in.png -o out.webp.

After you have the files

  1. Filenames exactly as printed above — the resolver matches on the name, not on the content.
  2. node scripts/assets/asset-manifest.mjs --write
  3. npm test — the manifest check fails loudly if step 2 was skipped.
  4. npm run build, then look at /, /authors and /categories.

If an image turns out wrong after it ships, delete the file and the site returns to the state it has now. Every one of these slots has a designed fallback; none of them 404s.
